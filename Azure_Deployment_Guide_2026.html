Azure Deployment Guide (2026 Edition)

Step-by-Step CI/CD Setup for Django 5.2 on Azure App Service using GitHub Actions
Django 5.2 LTS Python 3.11 Azure App Service Linux GitHub Actions CI/CD PostgreSQL Flexible Server Azure Cache for Redis
1 Phase 1: Unlock the Azure Security Gate (SCM Basic Auth)

In modern Azure releases, Basic Auth is restricted by default. SCM Basic Auth must be explicitly enabled to allow GitHub Actions Publish Profile authentication.

  1. Go to the Azure Portal and navigate to your App Service instance.
  2. In the left sidebar under Settings, click Configuration (or Environment variables).
  3. Select the General settings tab at the top.
  4. Scroll down to the Basic Auth section.
  5. Find SCM Basic Auth Publishing Credentials and toggle it to On.
  6. Click the Save button at the top of the blade.
2 Phase 2: Get the Master Key (Publish Profile)
  1. In the Azure Portal, click Overview on the left-hand menu to return to your App Service dashboard.
  2. In the top toolbar, click Get publish profile. This will download a .PublishSettings XML file to your computer.
  3. Open this downloaded file in any text editor (Notepad, VS Code).
  4. Copy every single line of text inside this file.
3 Phase 3: Hide the Key in the GitHub Vault
  1. Open your web browser and go to your GitHub repository: https://github.com/Driftingdane76/knowledgebase
  2. Click the Settings tab at the top of the repository.
  3. On the left sidebar, scroll down to Security, click Secrets and variables, and select Actions.
  4. Click the green New repository secret button.
  5. Under Name, type the following exactly:
    AZURE_WEBAPP_PUBLISH_PROFILE
  6. Under Secret, paste the complete block of XML code you copied earlier.
  7. Click Add secret.
4 Phase 4: Provision Azure Cache for Redis

The application uses Redis as the Celery message broker and result backend for background OCR processing. You must provision an Azure Cache for Redis instance before configuring environment settings.

  1. In the Azure Portal, search for Azure Cache for Redis and click Create.
  2. Choose the Basic C0 tier (sufficient for single-worker OCR queuing) and place it in the same region as your App Service (Denmark East).
  3. Once provisioned, navigate to the cache ➔ Settings ➔ Access Keys.
  4. Copy the Primary connection string. It will look like:
    <cachename>.redis.cache.windows.net:6380,password=<key>,ssl=True,abortConnect=False
  5. Convert it to a Django-compatible URL for use in the environment settings in Phase 5:
    rediss://<cachename>.redis.cache.windows.net:6380
    Note: rediss:// with double-s enables TLS — required by Azure Redis on port 6380.
Important: The Celery worker in startup.sh will fail to start if CELERY_BROKER_URL is not set or points to an unreachable Redis instance. This will prevent all OCR background jobs from running.
5 Phase 5: Mandatory Azure App Service Environment Settings

In the Azure Portal, navigate to your App Service ➔ Settings ➔ Configuration (or Environment variables) and add these critical settings:

Setting Name Value / Description
SCM_DO_BUILD_DURING_DEPLOYMENT true (Mandatory: enables Azure Oryx build to run pip install -r requirements.txt)
SCM_COMMAND_IDLE_TIMEOUT 1800 (Ensures package downloads never hit 600s timeout)
DJANGO_SETTINGS_MODULE core.settings
DEBUG False
SECRET_KEY Strong 50+ character random secret key for production
DB_ENGINE django.db.backends.postgresql
DB_NAME / DB_USER / DB_PASSWORD Azure Database for PostgreSQL credentials
DB_HOST / DB_PORT <your-server>.postgres.database.azure.com / 5432
ALLOWED_HOSTS kb-app-prod-dve8cybhcpgvaed8.denmarkeast-01.azurewebsites.net
REQUIRE_HTTPS True
CELERY_BROKER_URL rediss://<your-cache>.redis.cache.windows.net:6380/0 (Azure Cache for Redis — use rediss:// for TLS)
CELERY_RESULT_BACKEND rediss://<your-cache>.redis.cache.windows.net:6380/1
CACHE_URL rediss://<your-cache>.redis.cache.windows.net:6380/2

Startup Command (Under Configuration ➔ General settings ➔ Startup Command):

bash startup.sh
startup.sh installs Playwright browser binaries, starts the Celery worker (-Q default,ocr -c 1) in the background, then launches Gunicorn. Both processes share the same App Service container.
6 Phase 6: Create the GitHub Actions Workflow File
  1. At the root of your project, create the folder structure: .github/workflows/
  2. Inside workflows, create a file named azure-deploy.yml.
  3. Paste the exact code below into azure-deploy.yml:
name: Build and deploy Python app to Azure Web App - kb-app-prod on: push: branches: - main workflow_dispatch: jobs: build: runs-on: ubuntu-latest steps: - name: Checkout repository uses: actions/checkout@v4 - name: Set up Python 3.11 uses: actions/setup-python@v5 with: python-version: '3.11' - name: Upload artifact for deployment uses: actions/upload-artifact@v4 with: name: python-app path: | . !.git/ !.github/ !.venv/ !venv/ !antenv/ !__pycache__/ !*.sqlite3 !*.sqlite3-journal !.env !production_env !.agents/ !AGENTS.md !.cursorrules !test_output_images/ !test_htmls/ deploy: runs-on: ubuntu-latest needs: build steps: - name: Download artifact from build job uses: actions/download-artifact@v4 with: name: python-app - name: 'Deploy to Azure Web App' uses: azure/webapps-deploy@v3 id: deploy-to-webapp with: app-name: 'kb-app-prod' slot-name: 'Production' publish-profile: ${{ secrets.AZURE_WEBAPP_PUBLISH_PROFILE }}
7 Phase 7: Arm the Pipeline & Deploy

Run the following commands in Command Prompt (`cmd.exe`) to push the deployment pipeline to GitHub:

git add requirements.txt .github/workflows/azure-deploy.yml git commit -m "Configure PyTorch CPU index for lightweight Azure deployment" git push origin main
8 Phase 8: Monitor the Launch & Execute Migrations
  1. Go to your repository on GitHub.com and click the Actions tab.
  2. Click on the running workflow to watch live build and deployment logs.
  3. Once the jobs complete and turn into green checkmarks, navigate to your Azure web address:
    https://kb-app-prod-dve8cybhcpgvaed8.denmarkeast-01.azurewebsites.net
  4. Run Database Migrations: Open the SSH Console in Azure Portal (under Development Tools ➔ SSH) and execute:
    python manage.py migrate
Congratulations! Your Django 5.2 application is now live on Microsoft Azure with automated CI/CD continuous deployment.
